# На карте — отзывы организаций

Laravel 13 + Vue 3 (Composition API), Sanctum, spatie/laravel-data. Два экрана: вход и рабочее пространство организаций. Регистрация отключена, пользователей создаёт сидер или Artisan.

## Деплой через Docker

Готовые `docker-compose.yml` и многоэтапный `Dockerfile`: Nginx, PHP-FPM, PostgreSQL, отдельный worker и миграции. Настройка HTTPS, env, обновление и резервные копии описаны в [docker/README.md](docker/README.md).

## Локальный запуск

Нужны PHP с расширениями из composer.lock (включая DOM и SQLite), Composer, Node.js 22.12+ и npm. Парсер работает по ссылке через HTTP, Chromium не требуется.

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
php artisan app:create-user
npm ci
npm run build
php artisan serve --host=127.0.0.1 --port=8000
```

Не перезаписывайте существующий `.env`. В отдельном терминале запустите очередь:

```bash
php artisan queue:work --sleep=3 --tries=3 --timeout=600
```

Откройте http://localhost:8000. `app:create-user` запрашивает имя, email и пароль скрытым вводом. Альтернатива: задать `SEED_USER_EMAIL`, `SEED_USER_PASSWORD` и выполнить `php artisan db:seed`. Повторный сид обновляет пароль этого пользователя.

После изменения кода или конфигурации: `php artisan config:clear` и `php artisan queue:restart`. Для разработки интерфейса: `npm run dev`.

## Подход к парсингу и предел 600

Основной режим: GET `/maps/org/{id}/reviews/?page=N`, DOM-разбор `script.state-view`, поиск организации по точному ID, извлечение JSON `ratingData` и `reviewResults`. Это парсинг серверного состояния HTML, а не текстов визуальных карточек. Не нужно скроллить страницу или исполнять JavaScript для каждой порции.

Яндекс документирует доступность только последних 600 опубликованных отзывов: [справка Яндекс Бизнеса](https://yandex.ru/support/business-priority/ru/reviews/reviews). В исследованной крупной карточке страница 12 содержала ещё 50 отзывов, а 13 — метаданные без `reviewResults`, несмотря на большие `count/totalPages`.

Сбор завершается успешно после 600 уникальных валидных отзывов при большем счётчике выдачи. Снимок получает `outcome=source_limit_reached`, интерфейс поясняет ограничение. Отсутствие данных до достижения предела, CAPTCHA и сломанная схема остаются ошибками. Лимит числа страниц — отдельная страховка, его достижение не считается успехом. Сортировка источника может отличаться от хронологической: не обещаем, что выбранные отзывы — строго последние по дате.

Рейтинг, число оценок и число отзывов берутся из `ratingData` раздельно; рейтинг не вычисляется из выборки. `rating=0` в старых отзывах отображается как «Без оценки». `updatedTime` подписывается «Обновлён».

### 1. Устойчивость к изменениям источника

Проверяем HTML/state-view, схему JSON, обязательные поля, диапазон оценки, ID организации, номер страницы, прирост уникальных reviewId и завершение выдачи. Счётчики могут меняться во время обхода: изменения логируются, итог проверяется по последним данным. Повтор страниц или преждевременная остановка дают `partial`; неизвестная схема — `source_changed`, не пустой успешный результат.

Ошибки не перезаписывают предыдущий успешный снимок. Логи `storage/logs/laravel.log` содержат стадии `queued`, `started`, `metadata loaded`, `progress`, `completed`/`failed`, ID запуска и безопасные причины. Cookies и токены не должны попадать в логи или Git; HAR исключены из репозитория.

### 2. HTML/JSON против headless

| Способ                             | Преимущества                                             | Риски                                                                 |
| ---------------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------- |
| HTML со встроенным JSON (основной) | Один HTTP-запрос на страницу, без JS и браузерной сессии | Изменение state-view, ограничения выдачи, блокировка IP               |
| Внутренний JSON endpoint           | Компактный ответ, явные параметры пагинации              | Недокументированный контракт, CSRF, подпись `s`, cookies              |
| chrome-php/chrome                  | Выполняет страницу, получает сессионный контекст         | Потребление RAM/CPU, зависимости Chromium, CAPTCHA остаётся возможной |

Приложение использует только HTML со встроенным JSON. Поиск по названию и браузерный транспорт удалены. Подключение — полная ссылка с ID. Короткие ссылки `maps/-/...` пока не разрешаются; интерфейс просит полную ссылку. Внешние URL и произвольные редиректы не запрашиваются. CAPTCHA возвращается как ошибка источника.

### 3. Очередь и 50 филиалов

Контроллер валидирует ссылку и создаёт job, возвращая HTTP 202. Повторное подключение при активном запуске не создаёт вторую задачу. Job получает метаданные и страницы, обновляет прогресс; SPA опрашивает статус раз в 3 секунды. Сохранение данных и полного снимка атомарно. Чтение отзывов идёт из БД по 50 с устойчивой сортировкой, без новых обращений к Яндексу.

Три попытки для временных ошибок, backoff 30/120/300 секунд. Timeout 600, retry_after 720, срок блокировки 660 секунд. Начальная конфигурация — один worker. Для 50 филиалов: общий распределённый лимитер источника, разнесённый scheduler, мониторинг очереди и восстановление запусков после аварийного завершения процесса. Эти механизмы пока описаны, не реализованы. Не увеличивайте число workers без общего ограничения частоты.

### 4. Анти-бан

Между страницами пауза 500 мс. При `limited`/CAPTCHA задача завершается как `blocked`; бессмысленная серия повторов не запускается. Временные ошибки повторяются с backoff. Для регулярного объёма нужны cooldown на источник, jitter и обработка Retry-After. При использовании прокси IP и User-Agent следует сохранять в пределах сессии; ротацию выполнять между сессиями с контролем качества. Ротация прокси/UA, глобальный cooldown и CAPTCHA solver не реализованы. Скопированная сессия не гарантирует работу с другого IP.

### 5. Идемпотентность и история

`organizations`: владелец, уникальный `(user_id, source_id)`, исходные счётчики, статус, последний успешный запуск. `reviews`: уникальный `(organization_id, source_id)`, автор/текст/оценка/дата и `last_seen_run_id`. `parse_runs`: состояние, количество, ошибка и полный JSON-снимок результата.

Повторный сбор обновляет отзывы без дублей. Старые записи не удаляются, но текущий список и диаграмма читают только последний успешный набор. Для сравнения «было → стало» сравниваются два `snapshot` по reviewId и полям текста, оценки, автора и метаданным организации. Исчезновение из ограниченного окна не означает удаление отзыва на площадке. UI показывает последние пять запусков; подробный diff пока не реализован. Для долгого хранения нужны политика retention и сжатие снимков.

## Интерфейс и статистика

Счётчики Яндекса отдельно от размера сохранённой выборки. Распределение 0–5 и доля отзывов с оценкой 4–5 вычисляются по всем отзывам последнего успешного запуска, не только по текущей странице. Отзывы без оценки включены в знаменатель доли и показаны отдельной строкой. Статистика не экстраполируется на все отзывы площадки. Starter Kit страницы/компоненты удалены; фронтенд — Vue SPA без Inertia и UI-комплектов в сборке.

## Структура приложения

- `resources/js/MapsApp.vue` — композиция экрана; `components/maps` — вход, подключение и список организаций, детали, метрики, статистика, список/карточка отзыва и история запусков. Компоненты используют типизированные props/emits, формы — `v-model`.
- `composables/useMapsWorkspace.ts` — состояние, авторизация, выбор организации, пагинация и lifecycle опроса статуса. `lib/http.ts` — HTTP/CSRF и ошибки, `lib/format.ts` — форматирование, `types/maps.ts` — контракт данных.
- `app/Models/Organization`, `Review`, `ParseRun` — Eloquent-модели, casts и отношения; `User::organizations()` ограничивает доступ владельцем. `currentReviews()` задаёт выборку последнего успешного запуска.
- `Actions/Organizations/QueueOrganization` — транзакционное подключение и отправка job после commit; `PublishSnapshot` — атомарное обновление отзывов, метаданных и снимка через модели.
- `Queries/OrganizationDetails` — чтение данных и агрегация статистики через Eloquent; контроллер отвечает за HTTP и валидацию, job — за выполнение парсинга и повторные попытки.

`DB` используется для границ транзакций и afterCommit, а не как замена моделям. Исторический JSON cast в массив и скрыт от обычной сериализации API. Даты Eloquent возвращаются в ISO 8601 UTC. При неудачной записи любого отзыва транзакция откатывает весь новый снимок.

### Интеграция с источником

Используется существующий `lowel/laravel-service-maker`: `ReviewServiceInterface` наследует `ServiceInterface`, `ReviewServiceFactory` реализует `ServiceFactoryInterface`, а `YandexReviewService` наследует `AbstractService`. Пакет автоматически связывает интерфейс с фабрикой по соглашению об именах. Отдельная регистрация DI не требуется.

Фабрика выбирает площадку в `get(['provider' => 'yandex'])` и создаёт сервис в `getYandex()`. Сервис предоставляет `resolve()` и `parse()`. Внутри Яндекса HTML и разбор ссылок остаются отдельными небольшими классами. Job отвечает за статусы, прогресс, повторы и публикацию снимка, сервис — за полноту сбора.

`CollectionOutcome` различает полный сбор и достижение предела источника. API сохраняет прежнее поле `statistics.source_limited`, в том числе для исторических снимков со старым boolean. Ошибки источников наследуют `ReviewProviderException`.

Параметры нагрузки: `YANDEX_PAUSE_MILLISECONDS=500`, `YANDEX_MAX_PAGES=100`, `YANDEX_CONNECT_TIMEOUT=10`, `YANDEX_REQUEST_TIMEOUT=30`. Защитный предел страниц приводит к ошибке неполного сбора; константа 600 отражает предел источника. Ручной JSON-транспорт удалён: HTML-сбор всегда включён. Кеш первой страницы очищается между запусками.

## Сдача и развёртывание

**Хостинг и ссылка на Git ещё не подготовлены: обязательный пункт сдачи остаётся открытым.** Docker Compose добавлен: [инструкция деплоя](docker/README.md). Для VPS:

1. Установить PHP/Composer/Node, развернуть репозиторий; выполнить `composer install --no-dev --optimize-autoloader`, `npm ci`, `npm run build`.
2. Задать `.env`: `APP_ENV=production`, `APP_DEBUG=false`, HTTPS `APP_URL`, домен Sanctum, `SESSION_SECURE_COOKIE=true`, постоянную БД и ключ приложения. Выполнить миграции, создать пользователя. Web root — только `public`.
3. Настроить Nginx + PHP-FPM, HTTPS и права на storage/bootstrap/cache/SQLite для пользователя приложения. Закрытые профили и HAR не публиковать.
4. Запустить `php artisan queue:work --sleep=3 --tries=3 --timeout=600` через Supervisor/systemd с автозапуском и перезапуском. Worker должен использовать тот же релиз, `.env` и права доступа, что PHP-FPM.
5. После релиза: `php artisan config:cache`, `php artisan queue:restart`. Проверить `/up`, вход, подключение произвольной карточки, переход на вторую страницу, обновление без дублей, ошибку источника и работу worker после выхода из SSH.
6. Передать проверяющему URL, учётную запись по отдельному каналу и ссылку на репозиторий.

С большим запасом времени: автоматизированный deploy, мониторинг, recovery зависших запусков, общий лимитер, короткие ссылки, UI сравнения снимков и браузерные e2e-тесты.

## SOCKS5-прокси

```dotenv
YANDEX_PROXY="socks5h://username:password@proxy.example.com:1080"
```

Пустой `YANDEX_PROXY` оставляет прежние настройки подключения. Прокси применяется только к запросам Яндекса: HTML. `socks5h` передаёт разрешение DNS имени назначения прокси; `socks5` в PHP разрешает его локально. Нужен `ext-curl`. Спецсимволы в логине/пароле кодируйте как URL (`@` → `%40`, `#` → `%23`). Значение не выводится в сообщения об ошибках.

SOCKS5 поддерживает логин и пароль через PHP/curl. [SOCKS5/DNS в curl](https://curl.se/libcurl/c/CURLOPT_PROXY.html).

После настройки выполните `php artisan config:clear` (либо `config:cache` в production), затем `php artisan queue:restart`. Недоступный прокси приводит к ошибке запроса, прямого повторного подключения код не делает.

### Добавление площадок

```text
app/Services/Review/
  ReviewServiceInterface.php
  ReviewServiceFactory.php
  Exceptions/
  Enums/
  Providers/
    Yandex/
      YandexReviewService.php
      YandexHtmlPage.php
      YandexOrganizationUrl.php
app/Data/Review/
  ParseRequestData.php
  ParseResultData.php
  ...
```

```php
$service = app(ReviewServiceFactory::class)->get(['provider' => 'yandex']);
// Также поддерживается автоматический binding пакета:
$service = app()->makeWith(ReviewServiceInterface::class, ['provider' => 'yandex']);

$request = $service->resolve($url); // ParseRequestData(provider, sourceId, url)
$result = $service->parse($request, $onProgress);
```

`ParseRequestData` — один плоский DTO без cookies, сессии или произвольного массива опций. Транспортные настройки остаются внутри реализации. Callback прогресса передаётся отдельно и не сериализуется. Job хранит ID запуска, а DTO собирает из сохранённой организации.

Чтобы добавить 2ГИС, создайте `Providers/TwoGis/TwoGisReviewService`, наследующий `AbstractService` и реализующий `ReviewServiceInterface`; добавьте `getTwoGis()` и ветку `match` в `ReviewServiceFactory`. Реализуйте разбор ссылки и сбор в этой интеграции. Рабочей интеграции 2ГИС пока нет.

`POST /api/organizations` принимает `{ "provider": "yandex", "url": "https://yandex.ru/maps/org/123/" }`. По умолчанию используется Яндекс для совместимости текущего фронтенда. Неизвестная площадка отклоняется до сетевых запросов.

Поле `organizations.provider` сохраняет площадку, уникальность — `(user_id, provider, source_id)`. Миграция помечает старые записи как `yandex`. Перед запуском новой версии выполните `php artisan migrate`, `php artisan config:clear` и `php artisan queue:restart`. При обновлении карточки фронтенд передаёт сохранённую площадку. Для подключения новых карточек других площадок понадобится селектор в интерфейсе, когда появится вторая реальная интеграция.
